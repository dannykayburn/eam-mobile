Record View
Organization pill
Organization pill: defaults to the current user's own org (shown here as ORG1). Code only, no description — a new third category on the §15.1 exception list, distinct from Cost Code/Store (which show code + description) and from identifier fields — organization codes are short, memorized shorthand, and a rotating description alongside them adds clutter without helping identification. The LOV picker sheet still shows the description too, for selection clarity. Font is the plain .field-value treatment — same as any other field's value text — not the small muted monospace treatment used for codes-with-descriptions (Cost Code, Assigned To); since Org has no description sitting next to it here, it reads as the field's whole value, not a secondary code label. Required only when Insert Mode is the Record View standard (creating a brand-new top-level record, design-decisions-v3-1.md §19.9) — a List/Detail insert (a child record scoped to an existing parent) doesn't gate on it, since the parent record's own org already applies. Shown here in its required state (no Clear) as the more locked-down of the two cases.

User Defined Field 01
Inline text (≤255 chars): tap directly into the row and edit right there — no popup at all. A floating blue checkmark appears above the keyboard; tapping it (or Enter, or tapping away) commits the value and marks the form dirty. This supersedes the single-line edit sheet for plain text — the sheet is still used for currency/number below, just not for text.

Long-text: full-height text editor sheet, not a cramped inline input. Closing with unsaved edits swaps the close button for a red "Discard unsaved changes" pill; typing again dismisses the warning. No Clear button here — select all and delete instead. (Dictation is handled by the device's own keyboard, not a custom app control — nothing to build here beyond a plain text input.)

Comments: same long-text editor as above — inserting a new comment and updating an existing field's long text are the exact same pattern (full-screen editor, no Clear). Each comment has an ellipsis next to its timestamp for Edit / Delete / Copy, permission-driven — only the comment's own author sees Edit/Delete; everyone sees Copy.
