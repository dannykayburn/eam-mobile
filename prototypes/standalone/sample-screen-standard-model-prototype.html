Text, number, currency, date, time
User Defined Field 01
Inline text (≤255 chars): tap directly into the row and edit right there — no popup at all. Label sits on its own line, cursor starts left-aligned underneath it (not right-justified mid-line), and the value spans the full row width, wrapping to as many lines as needed — this is the field's permanent shape (2026-07-23 — was conditional, only going tall once text passed 24 characters; now always this taller shape from the start). A floating green checkmark appears above the keyboard; tapping it (or Enter, or tapping away) commits the value and marks the form dirty. This is the standard for any standalone free-text field NOT inside a collapsible container (Activity Notes, Checklist Notes, Insert Mode Description, this UDF01) — a same-shaped field that ever ends up inside a real collapsible container, or an actual multi-line textarea like Comments/Closing Comments, is a different case and keeps its own shape. This supersedes the single-line edit sheet for plain text — the sheet is still used for currency/number below, just not for text.

Date/Time: same custom calendar sheet as Date, plus a native <input type=time> row below the grid for the time portion. Start Time
Time Only (added 2026-07-21 — first field of this type in the app; locked here, then corrected on Book Labor's Start/End Time, which had shipped the wrong font before this rule existed): a native <input type=time> row, same .time-input class the Date/Time field above uses for its time portion — no date paired, no popup/sheet at all, tapping it opens the OS's own time picker directly (a real scroll wheel on iOS/Android; desktop shows its own platform spinner). Two rules that don't fall out automatically from "reuse the native input": Inter, not mono — a time-of-day value isn't a code, so it takes the same font as any other plain field value, not --font-mono. 24-hour "military" time only, never AM/PM — a deliberate business rule, not locale-driven (unlike dates, see below) — every Time Only input still carries lang="en-GB" as a best-effort hint, but verified live that it does not reliably work: modern Chrome renders time-input chrome off the browser's own UI language, not the page's lang attribute, so the native picker still showed AM/PM in testing. Accepted as a platform limitation (same category as the scroll-wheel-vs-spinner difference above) — the stored value and every bit of the app's own rendered text stay 24-hour regardless; only the native picker's own transient edit chrome is outside our control. Real devices should instead follow the OS's own 24-hour setting, which most EAM deployments enforce for technicians.
