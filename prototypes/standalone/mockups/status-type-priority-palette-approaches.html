The actual question: not "what hex," but how the colour budget splits across the 3 fields that can ever carry colour — Status, Type, Priority. Today Status is loudest (header pill), Type is medium (built this session), Priority is quietest. Each option below is a different, complete answer — shown on the header (WO 19257, top) and a WO List row (bottom) so the hierarchy is visible in context, not just as swatches.

Approach 2
Three grammars, same positions
Leaves today's visual hierarchy untouched (Status keeps the big pill, Type keeps its badge) — the change is that each field now uses a genuinely different kind of colour logic, so your eye learns to read the grammar, not just the hue. Status = semantic (green/outline/red = state). Type = categorical (one arbitrary hue per Type = identity). Priority = sequential — new: a real intensity ramp within one hue instead of flat text, Low→Critical getting darker/more filled.

Approach 3
Type as ambient theme

Approach 4 — resolves the red overlap
One shared wheel, no collisions
Status keeps its current shape and prominence (still the big pill) — this approach isn't about hierarchy, it's about correctness. Today Status-blocked and Priority-Critical are both the literal same --red for two different meanings. Here, --red is Status's alone ("this record is stuck," an operational fact); Priority Critical moves to Rose — borrowed from Type's own curated wheel, since Priority's urgency is closer to Type's "identity/severity" story than to Status's "state" story. Type and Priority now visibly share one wheel; Status is deliberately the odd one out, because it's the one field whose colour is genuinely a different kind of fact.
