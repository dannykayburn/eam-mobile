## Colors

Primary is a soft blue (`{colors.primary.main}`), reserved for CTAs, links, active states. `{colors.octave.main}` provides a branded monochrome pair (white-on-dark) for components that need an Octave-black/white identity instead of primary blue.

**Themes:** `colors` = dark theme tokens, `colorsLight` = light theme tokens, same names 1:1 (`colorsLight.primary.main`, etc). Both are equally valid — this doc doesn't privilege one as default; specify which one you're building against. Note the hex values differ between themes even for the same token — e.g. `primary.main` is `#89b1ff` (dark) vs `#0055ff` (light), not identical.

**Primitives:** `ui` (black/grey/white/blue), `status` (red/blue/yellow/green/orange/purple), `accent` (blazeOrange/aqua/harlequin/pink/blue/yellow) — 50–900 scales. Never reference these directly in components; always go through the semantic layer above.

**Gradients:** `colors.gradients.octave[0-6]` — restricted to Login/Splash/branded marketing surfaces only (the Unleash Mark). Any other use needs Visual Design sign-off.

## Typography

Two families: **Octave Display** for h1-h6 (headings), **Octave Sans** for everything else (subtitles, body, UI labels). Display starts light (300) at hero sizes, shifts to regular/medium at smaller headings.

## Icons (system-wide rule)

> **⚠ Temporary.** Material Symbols is a placeholder icon set, used until the visual design team redraws a custom outline icon set to replace it. Treat this as provisional, not a permanent decision — expect this section to be revised once custom icons ship.

**Every icon in every component is Material Symbols Outlined** (`material-symbols-outlined` font class), not a custom SVG. Variable font settings: `'FILL' 0, 'wght' 300, 'GRAD' 0, 'opsz' 20`, rendered at 20px font-size (scale up/down per component as needed, but keep these axis values). This supersedes any earlier assumption that components use `uxt-graphics` SVG icons (e.g. Button's `iconSvg` prop, Dropdown Button's chevron, Toggle Icon Button Group's icons) — those should all be read as Material Symbols in this system's actual usage, not the raw SVG paths uxt-react ships by default.

**Retroactive flag:** every component HTML preview built in this doc before this rule was confirmed (`button.html`, `dropdown-button.html`, `toggle-button-group.html`, `new-chat-button.html`, `chip.html`, `badge.html`) uses inline custom SVG icons/chevrons, not Material Symbols. These need to be swapped — see HANDOFF.md.

## Do's and Don'ts

### Do
- Reference semantic tokens only (`{colors.primary.main}`, `{colors.text.primary}`) in components.
- Map semantic → primitive per theme (light/dark) at the alias layer only.
- Use Material Symbols Outlined for every icon, everywhere — see Icons section above.

### Don't
- Never hardcode or reference `ui.*`, `status.*`, `accent.*` primitives directly in a component — **except** the New Chat Button, the one sanctioned exception, which fills with a pillar accent color by design (see Components → New Chat Button).
- Never invent a new primitive without adding it to the scale first.
- uxt-react ships more variants per component than this system uses (e.g. Input has outline/filled/standard). Only the variant documented under `components:` is canon here — the rest exist upstream but are intentionally excluded, not missing.

### Severity Semantics (which real-world state maps to which severity)

- **critical:** overdue, important, blocking, destructive/failed states → red.
- **warning:** soon due, missing, approaching a limit → yellow (bg) / amber text — see the `chip-status-fill` warning cross-hue note above.
- **info:** on track, approved, "good" — anything positive/healthy → **blue**, not green. Green (`success`) exists as a severity but is not the default "good" state in this system's real usage; blue is.
- **neutral:** time-based/informational context (e.g. "this week") that isn't itself a judgment → grey.
- *(more mappings to be added as they come up)*

### Multiple Buttons (rows/stacks)
- Primary action is always `button-contained-primary` (filled). Secondary is always `button-outlined-primary`. Never two filled buttons in the same group.
- Horizontal groups: `{spacing.xs}` (8px) gap between buttons.
- Vertical stacks: `{spacing.xs}` (8px) gap, buttons stretch to equal width.
- Primary action goes leftmost (horizontal) or topmost (vertical); secondary/outlined follows to its right/below.

## Components

### Buttons

Three variants (`variant` prop): **outlined** (default, border + transparent fill), **contained** (solid fill + contrast text), **text** (no border/fill, link-style). Shared base: 36px height, `{typography.button}` label (capitalized), 1px `{colors.border.control}` border.

**Shape** (`shape` prop): `stadium` only (full pill — `{rounded.xxl}` 24px in our scale) — used for all CTAs (contained is primary, and text variant is sometimes used as a lower-emphasis CTA too). uxt-react also offers `rounded-rectangle` (`{rounded.xs}` 4px, squared) but this system doesn't use it.

**Leading icon:** optional `iconSvg` prop renders an icon before the label (uses `uxt-graphics` icon set). Tight gap between icon and label — `{spacing.xxs}` (4px), not `{spacing.xs}`.

**`button-contained-primary`** — filled pill, primary tone. Background `{colors.primary.main}`, text `{colors.primary.contrastText}`.

**`button-outlined-primary`** — transparent fill, primary-colored border + text. Same shape/height as contained.

**`button-outlined-secondary`** — this system's actual "secondary button": transparent fill, grey `{colors.border.control}` border, `{colors.text.primary}` (black/near-black) text — **not** primary blue. This overrides uxt-react's default `tone="secondary"` styling (which follows `theme.palette.secondary.main`, undocumented in the Storybook palette — see flag below).

**`button-text-primary`** — no border, no fill, tighter horizontal padding (`{spacing.xs}` vs `{spacing.md}`).

**States:** hover/active apply a semi-transparent overlay (`{colors.action.hover}` / `{colors.action.active}`) over the button rather than changing the base color. Focus swaps the border to `ui.blue[500]` (a rare direct primitive reference in the real component — flagged, not semantic-token clean). Disabled drops opacity to 0.5 and blocks pointer events.

**Full tone list** (`tone` prop): `primary` (default), `secondary`, `error`, `warning`, `info`, `success`, `octave`, and the pillar tones `design`, `build`, `operate`, `protect`, `crossPillar`. All follow the same outlined/contained/text structure, swapping only the tone's semantic color — **except secondary**, which this system overrides per the button-outlined-secondary spec above.

**Flag:** uxt-react's Semantic Colors Storybook page documents no `secondary.*` token group, even though `Button` references `theme.palette.secondary.main` internally. Don't build against that undocumented value — use the black-text/grey-border spec above instead.

### Text Inputs

Outline only (chosen as the system default — filled/standard variants exist in uxt-react but aren't used here).

**`text-input`** — full border box. Transparent background, 1px `{colors.border.control}` border, `{rounded.md}` (8px) radius, 40px height, `{typography.body1}` value text.

**States:**
- **Hover** (not focused): border/rule shifts to `{colors.text.link}`.
- **Focused**: label recolors to `{colors.text.link}`; border/rule shifts to `{colors.action.focus}` and doubles in width (2px).
- **Error**: border, value text, and label all switch to `{colors.text.error}` — overrides focus/hover.
- **Disabled**: opacity 0.5, no interaction.

### Toggle Button Group

A segmented control — group of Buttons in a single bordered pill container (`{colors.border.divider}` 1px border, `{rounded.pill}`). `{spacing.xxs}` gap between items when `showSeparators` is off; a 1px divider line between items when on. Supports `single` (default, radio-like, sliding selection indicator) or `multiple` (checkbox-like, no sliding indicator) selection modes.

**Active item — both selection modes, unified:** solid white/`{colors.background.card}` pill behind the selected item, `{colors.primary.main}` (blue) text/icon, real drop shadow lifting it off the group's background. Single-select and multiple-select now render identically.

**Note — this is an override, not the uxt-react default.** The live Storybook Demo story actually renders single-select active text as black (`#1a1a1f`) on a white pill (verified: `background-color: #ffffff`, `color: #1a1a1f`), and multiple-select active as blue text on a flat `{colors.action.selected}` fill with no shadow — no white pill, no elevation. This system deliberately overrides both to the unified blue-text/white-pill/shadow treatment above, same pattern as the secondary button override. See HANDOFF.md. Unselected items show `{colors.text.secondary}` (grey) text, no background, until hovered — hover on an unselected item gets a light `{colors.action.hover}` tint.

Focus ring: `0 0 0 2px {colors.primary.main}`, shape-matched to the group's corners.

**Shape** follows the same `stadium`/`rounded-rectangle`/`rectangle` options as Button — this system only uses `stadium`, consistent with the Button rule.

### Toggle Icon Button Group

Same pattern as Toggle Button Group but icon-only items (wraps `ToggleIconButton`, not `Button`). Adds a `size` prop controlling item height: `small` 24px, `regular` 32px (default), `large` 40px. Active-state colors (white/`{colors.background.card}` pill, `{colors.text.primary}` icon, shadow) are inferred to match Toggle Button Group's live-verified behavior by code-pattern parity — not independently confirmed live.

**Correction:** uxt-react ships a **separate, dedicated `ThemeToggleGroup` component** (confirmed in Storybook sidebar under Buttons & Actions, alongside ToggleButtonGroup/ToggleIconButton/ToggleIconButtonGroup). Use that for actual light/dark theme switching — don't assume a generic 2-item `toggle-icon-button-group` is the right primitive; `ThemeToggleGroup` hasn't been pulled into this doc yet.

### New Chat Button

Built from `SplitButton` (a contained-primary Button glued to a chevron IconButton, flat corners where they meet, no gap between — inner corners squared, outer corners follow the group's `{rounded.pill}` shape).

**Unique to this component:** it's the one place in the system that fills with a **pillar accent color** instead of `{colors.primary.main}` — `{colors.pillar.design}` (aqua), `.build` (yellow), `.operate` (pink), `.protect` (green) — chosen by which pillar the product belongs to. Text is `#1a1a1f` (near-black ink) on design/build/protect — **except operate (pink)**, which flips to white text, since black is unreadable against `#ff00c7`. Text color is per-pillar, not universal.

**Width:** normally stretches to fill its container (e.g. a sidebar/rail), not hug-content — the label segment grows (`flex: 1 1 auto`) but its text stays centered (not left-aligned) within the grown space; the chevron segment stays fixed at 36px.

### Dropdown Button

Three trigger variants — same 36px height and `{typography.button}` label as the standard Button, `{rounded.pill}` shape, black text by default rather than primary blue. Chevron optional, label/chevron separated by `{spacing.xs}`, chevron rotates 180° on open (200ms ease-in-out).

**`dropdown-button-stadium`** — default. Transparent fill, `{colors.border.control}` (grey) border, `{colors.text.primary}` (black) text — same border treatment as `button-outlined-secondary`, not a heavier black outline.

**`dropdown-button-stadium-contained`** — filled. Background `{colors.primary.main}`, text `{colors.primary.contrastText}`.

**`dropdown-button-stadium-text`** — no border/fill, tight padding (`{spacing.xs}`).

**No-icon:** any of the above without the trailing chevron — same trigger, chevron simply omitted (used when the "dropdown-ness" is conveyed by context, not the icon).

**`dropdown-panel`** — the floating content panel. Background `{colors.background.paper}`, `{rounded.md}` (8px) corners, min-width 100px, max-height 80vh (scrolls internally past that), 4px offset from the trigger, elevation level 1. Content is arbitrary (not a fixed menu-item list) — this is a generic dropdown/popover primitive, not a specific select/menu component.

### Status Dot

A small colored circle (6px, `{colors.severity.*}` fill) plus a regular-case label (not uppercase), `{spacing.xs}` gap between them. Label uses `{typography.body2}`, colored `{colors.text.primary}` regardless of dot severity.

**Five severities:** `critical` (error/red), `warning` (yellow), `success` (green), `info` (blue), `neutral` (grey — the one severity that pulls from a `ui.*` primitive directly, `ui.grey[100]`, rather than a semantic status color).

**Label is optional** — when omitted, the severity name itself is used as the label (e.g. just "critical").

**Pulsate:** optional prop adds a second ring inside the dot that scales from 1× to 1.8× while fading opacity 0.45 → 0, looping every 2.4s — a "live/active" heartbeat effect, not used on static status indicators.

**`status-dot-critical-emphasis`** — a heavier-weight critical variant: same red dot, but the label text also recolors to `{colors.text.error}` (not `{colors.text.primary}`) for extra visual urgency. Not present in the base uxt-react component (which always keeps label text `{colors.text.primary}` regardless of severity) — a product-level addition for genuinely urgent critical states, used sparingly.

### Chip

A compact, clickable pill: `{typography.button}` (14px), 36px height — both overridden from uxt-react's default (`{typography.body1}`/32px) to match the Button. 1px `{colors.border.divider}` border, `{spacing.md}` (16px) horizontal padding by default.

**Icon padding asymmetry:** when a leading icon or trailing delete icon is present, the padding on that side tightens to `{spacing.xs}` (8px) — the icon carries its own visual weight, so the icon-side padding is `0 {spacing.md} 0 {spacing.xs}` (leading icon) or `0 {spacing.xs} 0 {spacing.md}` (trailing delete). The side without an icon keeps the full 16px.

**Icons are Material Symbols Outlined** (`material-symbols-outlined` font class), not uxt-graphics SVGs — variable font settings `'FILL' 0, 'wght' 300, 'GRAD' 0, 'opsz' 20`, rendered at 20px font-size. This is a chip-specific rule (confirmed for Chip's leading/delete icons); doesn't necessarily extend to other components' icon slots (e.g. Button's `iconSvg` still uses uxt-graphics) unless confirmed separately.

**Shape:** `stadium` only (`{rounded.pill}`) — same rule as Button. uxt-react also offers `rounded-rectangle` but this system doesn't use it.

**States:** hover/active apply the standard `{colors.action.hover}` / `{colors.action.active}` overlay. `isActive` (toggled/selected) fills background + border with `{colors.action.selected}` — this is the chip's persistent "selected" look, distinct from the transient hover/active overlay.

**`chip-status-dot`** — the leading icon slot swapped for a small colored circle (6px, same severities as Status Dot: critical/warning/success/info/neutral) instead of an SVG icon. This is how "chip with a status dot" is built — not a separate component, a composition of Chip's icon slot + Status Dot's color logic.

**`chip-status-fill`** — a bolder variant: the whole chip background fills with a pale `[50]` tint (not just the dot), text and dot both recolor to a dark `[900]` step, no border. Same 36px height as the standard Button, not the 32px default chip height. Real product example set: "Overdue" (critical), "Soon Due" (warning), "On Track" (info), "This Week" (neutral).

- **critical:** `status.red[50]` bg / `status.red[900]` text — 5.59:1 ✅ passes AA
- **warning:** `status.yellow[50]` bg / **`status.orange[900]`** text (cross-hue — amber reads better than yellow at any step) — 3.61:1, passes only the 3:1 UI-component bar
- **info:** `ui.blue[50]` bg / `ui.blue[900]` text — 7.95:1 ✅ passes AAA
- **neutral:** `ui.white[300]` bg (not `ui.grey[50]` — that read too dark against the others) / `ui.grey[900]` text and dot

**WCAG flag:** yellow cannot pass at any step of its own scale (worst case 1.75:1 at `[900]`/`[50]`) — hence the cross-hue swap to `status.orange[900]` for warning's text, which still only reaches 3.61:1. Blue and neutral pass cleanly; critical passes; warning remains the one open gap. See HANDOFF.md.

### Multi-Select Chips (usage pattern, not a distinct component)

A row of `Chip` components, each independently toggleable via `isActive` / `onIsActiveChange` — i.e. `Chip` already supports multi-select natively; a "multi-select chip group" is just several Chips in a row/wrap layout with no additional container logic. No shared selection state needed (unlike Toggle Button Group, where the group itself manages which item(s) are active) — each chip owns its own active state independently.

### Badge

Wraps a child element (icon, avatar, nav item) with a small overlay indicator, absolutely positioned at its top-right corner. Two variants:

**`badge-count`** — numeric. 16px height, `{rounded.md}` (8px, reads as fully-rounded at this height), `{spacing.xxs}` horizontal padding, `{colors.error.main}` background, white text. Caps at `maxCount` (default 99) — beyond that, shows `"99+"` rather than the literal number.

**`badge-dot`** — no number, just presence. 8px circle, `{rounded.xs}` (4px, fully round at this size), same `{colors.error.main}` background.

Both default to `{colors.error.main}` — badges in this system read as "something needs attention" (notifications, unread counts), not a general-purpose multi-color indicator like Status Dot.

### Dashboard Summary Card

**New component — not in uxt-react.** Pulled from the InConcert product preview (`product-previews/inconcert/inconcert.html`), a product-level composition built from `Card` + a custom chart body, not a base library component. Source markup: `.project-card.project-card--chart` (a `data-uxt-component="Card"` article).

**Shared anatomy across all three variants:**
- Card shell: `{colors.background.card}` bg, `{rounded.sm}` (8px) corners, `{spacing.lg}` (24px) padding, a soft inset-hairline + double drop-shadow (not a standard elevation level — distinct from Button/Toggle's shadow recipe).
- Header: title (left, with a small info-icon affordance) + a muted right-aligned summary string (e.g. "8 active", "18 across 4 projects"). Title and right-label share one row, space-between.

**Three interchangeable chart-body variants, same header:**

**`dashboard-summary-card-ring`** — a donut/ring chart (140px, 16px ring thickness, small gap between segments, rounded segment caps) with a centered value + label overlay, paired with a legend list (colored dot + label + count) to its right. Built with d3 (`d3.pie()` / `d3.arc()`) in the source — for a static HTML preview, approximate with a CSS `conic-gradient` ring instead of pulling in d3.

**`dashboard-summary-card-bar`** — horizontal bar rows (name + track + count per row), plus a legend footer band (colored dots + labels) separated by a top border, full-bleed to the card edges (negative-margin trick, not padding).

**`dashboard-summary-card-text`** — a big bespoke-size number (72px, no matching typography token — this is a one-off display size, not `{typography.h1}` or any existing scale step) + a label, plus the same full-bleed footer-band pattern as the bar variant (typically one status line with a colored dot).

**Flag for HANDOFF:** several sub-values here don't map cleanly to existing DESIGN.md tokens (the 72px stat value, the 28px donut center value, the 10px donut center label) — these are bespoke sizes specific to this card, not deviations of an existing type scale step. Don't force them into `{typography.h1}` etc; document them as their own thing.

**`dashboard-summary-card-milestone`** — a 4th variant, structurally different from the other three: no shared `card__head` eyebrow row, self-contained instead (`.milestone`, not `.project-card--chart`). Shows a milestone name, a target date, a status pill (icon + text, 4 states: complete/progress/planned/active), then a percentage + fraction row and a progress bar. Pulled from `.milestone-card__grid` inside the separate **Milestone Overview Card** component (mini-cards + a cumulative timeline bar) — that outer component hasn't been pulled into DESIGN.md yet, only this individual mini-card has.

### Document Progress Panel

**New component — not in uxt-react.** A wide panel wrapping a 3-column grid of `chart-card`s, each breaking down document counts a different way. Source: `product-previews/inconcert/inconcert.html`, `.milestone-card.milestone-card--large` (outer) + `.chart-grid` (3-column) + `.chart-card` (each column).

**Outer wrapper** reuses the exact same shell as the Milestone Overview Card (`.milestone-card` — same background, radius, padding, shadow), just with a **scope-selector Chip** on the header-right instead of a configure button — a Chip that opens a plant/project-picker DropdownList, labeled e.g. "PAP Unit 77" with a caret.

**Each `chart-card`:** eyebrow (e.g. "Document type") + bold title (a total count, e.g. "182 docs") + a muted sub-line (e.g. "6 types · 182 docs"), a configure-gear button (top-right, same 32px bordered-square spec as Milestone Overview's configure button), then one of two body layouts:

**`document-progress-panel-doc-row`** (used by "Document Type" and "Discipline" cards) — each row is a **stacked multi-segment bar**, not a single-color bar: issued (green) / in review (blue) / in progress (amber) / late (red) segments packed into one 6px track, label left, doc count right. Rows separated by a hairline divider, last row has none.

**`document-progress-panel-area-row`** (used by "Area / Unit" card) — grouped differently: an area/unit header (name + overall readiness %, color-coded good/mid/bad) followed by single-fill readiness bars per document type underneath it, tighter row spacing than doc-row, no dividers between rows.

**Configure popovers — two distinct interaction patterns:**
- **Checklist mode** ("Document Type", "Area/Unit"): a 2-column checkbox grid, capped selection ("Max of 6 reached — uncheck one to swap"), no reordering.
- **Reorder mode** ("Discipline"): a **draggable** priority-ordered list — 6-dot grip handle icon, rank number, checkbox, label per row. Same drag-to-reorder pattern as the Milestone Overview Card's own configure popover (drag to reorder, check to show/hide).

**Legend footer:** same full-bleed border-top band pattern used elsewhere in this doc (Dashboard Summary Card's bar/text variants) — 4 semantic dots (issued/review/progress/late).

**Fully functional in the preview:** the configure popovers are real, not decorative — checkboxes actually show/hide their matching row (Document Type, Area/Unit), and the Discipline popover's grip-handle drag actually reorders that list (native HTML5 drag events), which live-reorders the real chart bars to match and re-numbers the rank badges. Lives in `dashboard-summary-card.html` alongside the summary card variants (not a separate file — kept together per direct instruction).
